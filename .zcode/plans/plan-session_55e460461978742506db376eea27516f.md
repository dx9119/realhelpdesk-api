# План: перевод проекта на версию 1.0.0

Контекст по факту: версия проекта сейчас в 6 местах; CI пушит образы только как `sha-<sha>`+`latest`; deploy на git-теге `v*` разворачивает `IMAGE_TAG=sha-<sha>` (имя тега в образ не попадает); guard-тесты на строку версии не завязаны; `APP_JAR` в Makefile — мёртвая переменная (нигде не используется, потребители jar ходят по glob `target/*.jar`).

## 1. pom.xml — версия проекта (защищённый файл: правка только строки координат)
- `pom.xml:17`: `<version>0.0.1-SNAPSHOT</version>` → `<version>1.0.0</version>`.
- Секции плагинов/качества не трогаются. Итоговый артефакт: `realhelpdesk-1.0.0.jar` (Dockerfile и `check-image.sh` используют `target/*.jar` — ничего не ломается).

## 2. Makefile — мёртвая переменная APP_JAR
- Удалить строку 8 `APP_JAR ?= target/realhelpdesk-0.0.1-SNAPSHOT.jar` (не используется ни одним рецептом/скриптом). Альтернатива, если хотите сохранить — обновить на `realhelpdesk-1.0.0.jar`; рекомендую удаление.

## 3. Телеметрия и логи — дефолт версии сервиса
- `application.properties:294` и `:315`: `${OTEL_SERVICE_VERSION:0.0.1-SNAPSHOT}` → `${OTEL_SERVICE_VERSION:1.0.0}` (ресурс-атрибут OTel `service.version` + поле ECS в JSON-логах).
- Локальный игнорируемый `infrastructure/.env:331`: `OTEL_SERVICE_VERSION=1.0.0` (в git не попадает).

## 4. OpenAPI-контракт
- `OpenApiConfiguration.java:30`: `.version("0.0.1-SNAPSHOT")` → `.version("1.0.0")`.
- Поправить комментарий над ней: ссылка на `.env.dev.example` устарела (переменной там нет) — дефолт живёт в схеме `application.properties`.

## 5. CI: версионные теги образов (`.github/workflows/ci.yml`)
- Триггеры push: добавить `tags: ["v*"]` (сейчас — только `branches: [main]`).
- job `docker`: при пуше тега дополнительно пушить в ghcr.io образ с тегом `v1.0.0` (имя git-тега, `${GITHUB_REF_NAME}`) рядом с `sha-<sha>` и `latest`; при пуше в main — без изменений (`sha-<sha>` + `latest`).

## 6. Деплой по версии (`.github/workflows/deploy.yml`)
- Шаг «Определить тег образа»: для события тега `IMAGE_TAG=${GITHUB_REF_NAME}` (например `v1.0.0`) вместо `sha-<sha>`; `workflow_dispatch` — без изменений (ручной input).
- Обновить шапку-комментарий и описание input: «sha-<git_sha>, v-тег или latest».
- Итог: `.env` на сервере после релиза читаемо — `IMAGE_TAG=v1.0.0`, откат возвращается на предыдущее значение.

## 7. Документация
- `docs/getting-started.md` §3.5: «IMAGE_TAG=sha-<git_sha>» → «IMAGE_TAG=<имя тега> (v1.0.0)»; §4.2 диаграмма — согласовать.
- README: схема запуска уже описывает деплой по тегу — не меняется.

## 8. Git: релизный коммит и тег
1. Коммит `chore(release): версия 1.0.0` (все правки выше одним коммитом).
2. Аннотированный тег `git tag -a v1.0.0 -m "RealHelpDesk 1.0.0"` на этом коммите.
3. `git push origin main` — запустит CI (сборка, пуш `sha-*`/`latest`).
4. `git push origin v1.0.0` — **запускает deploy.yml: автоматический деплой `v1.0.0` на production** (health-gate 90 с, авто-откат на предыдущий IMAGE_TAG при провале). Тег создаётся локально сразу, но пункт 4 выполняю только как явный финальный шаг — если хотите деплоить сами, скажите, и я остановлюсь после пункта 3.

## Проверки перед коммитом
- `./mvnw -q validate` — координаты собираются;
- `make check-ci` — обязательный гейт (правился pom.xml);
- smoke: `make build` → `target/realhelpdesk-1.0.0.jar`.

## Намеренно не входит
- `build-info` goal в pom (показ версии сборки в `/actuator/info` автоматически) — отдельная задача, правка plugin-секции;
- CHANGELOG.md — не запрашивался.
