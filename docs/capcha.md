# Капча

Капча защищает две анонимные операции — регистрацию и запрос кода на email —
от массовых ботов. Вместо картинки с искажённым текстом используется
Proof-of-Work: сервер выдаёт подписанное задание, браузер решает его без
участия человека, а при подозрительной активности сервер повышает сложность
или переключает клиента на интерактивное задание с эмодзи.

Реализация — `core/security/localjwt/captcha`, клиентский виджет —
`static/captcha/widget.js`.

## Как это работает

Два уровня задания и три независимых сигнала:

| Уровень | Когда выдаётся | Что делает клиент |
|---|---|---|
| `pow` | По умолчанию; для IP с мягким риском — с повышенной сложностью | Подбирает `nonce`, при котором `SHA-256(salt + ":" + nonce)` имеет заданное число ведущих нулевых бит |
| `emoji` | Распределённая атака: провалы нескольких IP одной подсети | Отмечает в сетке 3×3 глифы нужной категории или один указанный глиф |

Сигналы, не зависящие от уровня:

- **honeypot** — невидимое человеку поле `website` в форме регистрации; заполнено → отказ;
- **минимальное время заполнения** — форма, отправленная раньше
  `CAPTCHA_MIN_FILL_SECONDS` после выдачи задания, отклоняется;
- **одноразовость** — и challenge, и выданный токен принимаются ровно один раз.

Сервер не хранит выданные задания: challenge — JWT, подписанный
HMAC-SHA256 секретом `CAPTCHA_HMAC_SECRET`, с claims `action`, `level`,
`exp`. В памяти живёт только реестр израсходованных идентификаторов
(`UsedTokenStore`, Caffeine: до 50 000 записей, срок — максимум из TTL
challenge и токена плюс минута).

## Флоу

```
Клиент                            Сервер
  │  POST /captcha/challenge        │
  │  { action }                     │  оценивает риск по IP
  │ ───────────────────────────────►│  подписывает challenge (pow | emoji)
  │ ◄───────────────────────────────│
  │  { challengeId, type, params, expiresAt }
  │                                 │
  │  решает задание локально        │
  │  (PoW — в Web Worker)           │
  │                                 │
  │  POST /captcha/solve            │  проверяет подпись, срок, ответ,
  │  { challengeId, nonce|answer }  │  неизрасходованность
  │ ───────────────────────────────►│
  │ ◄───────────────────────────────│
  │  { captchaToken }               │
  │                                 │
  │  POST /auth/register            │  verifyRegistration: honeypot,
  │  { captchaToken, ... }          │  подпись, срок, action, min-fill,
  │  или POST /email/codes          │  одноразовость
  │  X-Captcha-Token: ...           │
  │ ───────────────────────────────►│
```

Действия (`action`) фиксированы: `register` и `email-code`. Токен,
выданный на одно действие, на другом не принимается.

При `CAPTCHA_ENABLED=false` проверка токена пропускается (fail-open) — так
локальная разработка не требует решать PoW. Honeypot проверяется всегда.
В рабочем контуре `ProdPreflightValidator` не даёт стартовать с выключенной
капчей или со слабым секретом.

## Контракт API

| Метод и путь | Тело | Ответ |
|---|---|---|
| `POST /api/v1/captcha/challenge` | `{ action: "register" \| "email-code" }` | `{ challengeId, type: "pow" \| "emoji", params, expiresAt }` |
| `POST /api/v1/captcha/solve` | `{ challengeId, nonce }` для `pow` или `{ challengeId, answer: [индексы] }` для `emoji` | `{ captchaToken }` |

`params` зависит от уровня: для `pow` — `{ salt, difficulty }`, для `emoji` —
`{ prompt, cells: [9 глифов] }`. Незаполненные поля не сериализуются.

Оба эндпоинта анонимные (белый список security) и ограничены
рейт-лимитом `30 запросов / 60 с` каждый.

Провал капчи — `400` в формате problem+json с машинным полем `code`:

| `code` | Причина |
|---|---|
| `missing_token` | Токен не передан |
| `invalid` | Подпись не сходится, битый формат, неизвестное действие |
| `expired` | Истёк challenge или токен |
| `replayed` | Токен или challenge уже использованы |
| `wrong_type` | Предъявлен challenge вместо токена или наоборот |
| `wrong_action` | Токен выдан на другое действие |
| `too_fast` | Форма отправлена раньше `CAPTCHA_MIN_FILL_SECONDS` |
| `pow_failed` | PoW не решён: хэш не набрал нужное число нулевых бит |
| `wrong_answer` | Эмодзи-задание решено неверно |
| `honeypot` | Заполнено невидимое поле `website` |

## Оценка риска

`CaptchaRiskService` считает провалы в скользящем окне и выбирает уровень
следующего задания. Привязка к IP — только сигнал, не блокировка: мобильные
сети и NAT меняют адрес, поэтому один адрес не наказывает всех клиентов
за ним.

| Сигнал | Порог | Отклик |
|---|---|---|
| Провалы одного IP за окно | `CAPTCHA_RISK_FAILURE_THRESHOLD` | Мягкий риск: к сложности PoW добавляется `CAPTCHA_RISK_ELEVATED_DIFFICULTY_BONUS` бит (не выше 26) |
| Провалы разных IP одной подсети | `CAPTCHA_RISK_SUBNET_OFFENDER_THRESHOLD` | Эмодзи-задание (если `CAPTCHA_EMOJI_ENABLED=true`) |

Подсеть определяется префиксом: `CAPTCHA_RISK_SUBNET_PREFIX_V4` (по
умолчанию `/24`) и `CAPTCHA_RISK_SUBNET_PREFIX_V6` (`/64`). Счётчик IP
сбрасывается после успешной проверки.

## Параметры

Дефолты заданы в схеме `captcha.*` в `application.properties`
(`${CAPTCHA_…:default}`); переопределение для среды — переменные окружения
из `infrastructure/.env`.

| Переменная | Назначение | Диапазон / дефолт |
|---|---|---|
| `CAPTCHA_ENABLED` | Включение проверки токена; `false` — fail-open | дефолт `false`; в prod — `true` (требование preflight) |
| `CAPTCHA_HMAC_SECRET` | Секрет подписи challenge и токенов | ≥ 32 байт, генерируется `make env` |
| `CAPTCHA_POW_DIFFICULTY` | Число ведущих нулевых бит SHA-256 | 1..26, дефолт 18 |
| `CAPTCHA_CHALLENGE_TTL_SECONDS` | Срок жизни задания | дефолт 300 |
| `CAPTCHA_TOKEN_TTL_SECONDS` | Срок жизни выданного токена | дефолт 300 |
| `CAPTCHA_MIN_FILL_SECONDS` | Минимум секунд от выдачи задания до отправки формы; `0` — проверка отключена | dev 0, prod 3 |
| `CAPTCHA_EMOJI_ENABLED` | Эскалация на эмодзи-уровень (kill-switch) | дефолт `true` |
| `CAPTCHA_RISK_FAILURE_THRESHOLD` | Провалов одного IP для мягкого риска | 1..1000, дефолт 5 |
| `CAPTCHA_RISK_FAILURE_WINDOW_SECONDS` | Окно подсчёта провалов | 10..86400, дефолт 600 |
| `CAPTCHA_RISK_ELEVATED_DIFFICULTY_BONUS` | Добавка бит к сложности при мягком риске | 1..26, дефолт 3 |
| `CAPTCHA_RISK_SUBNET_OFFENDER_THRESHOLD` | Разных IP подсети для эмодзи-эскалации | 1..1000, дефолт 3 |
| `CAPTCHA_RISK_SUBNET_PREFIX_V4` | Префикс подсети IPv4 | 1..32, дефолт 24 |
| `CAPTCHA_RISK_SUBNET_PREFIX_V6` | Префикс подсети IPv6 | 1..128, дефолт 64 |

Сложность PoW — основной параметр, влияющий на время решения: 18 бит — это
в среднем 2^18 хэшей (доли секунды в браузере), 20 бит — заметно дольше.
Значение подбирается замерами на целевых устройствах.

## Клиентский виджет

`GET /captcha/widget.js` — самодостаточный скрипт без зависимостей:

```js
const token = await window.RealHelpCaptcha.getToken('register');
// token → поле captchaToken в теле POST /api/v1/auth/register
// token → заголовок X-Captcha-Token для POST /api/v1/email/codes
```

Виджет последовательно запрашивает challenge, решает его (PoW — в Web
Worker, при недоступности воркера — на основном потоке; эмодзи — оверлеем
поверх страницы) и обменивает решение на токен. Отмена человеком
отклоняет `Promise` с `error.code = 'cancelled'`, кнопка «Другое задание»
запрашивает новый challenge. Все POST'ы несут `X-Requested-With` — этого
требует CSRF-фильтр.

## Метрики

| Метрика | Теги | Смысл |
|---|---|---|
| `captcha.challenge.issued` | `type` (`pow`/`emoji`) | Сколько заданий выдано и какая доля — эскалация |
| `captcha.verification` | `type`, `result` (`success`/`failure`), `reason` | Итоги проверок; `reason` — код из таблицы выше |
| `auth.attempts` | `type="captcha"`, `result` | Сводный счётчик попыток аутентификации |

По `reason` видно, отсекает ли PoW ботов (`pow_failed`), ловит ли повторное
использование (`replayed`) и не деградировала ли форма (`too_fast`,
`wrong_answer`).

## Ограничения

Реестр израсходованных токенов и счётчики риска живут в памяти процесса.
Одна инстанция приложения — этого достаточно; при горизонтальном
масштабировании нужен общий стор (Redis), иначе повторное использование
токена на другой реплике не будет замечено.

Внешние анти-бот провайдеры (Turnstile, SmartCaptcha, hCaptcha) не
используются: все сигналы считаются локально.
