# Runbook: NoNewTickets

**Алерт**: `increase(tickets_total[2h]) == 0` в рабочее время (пн–пт, 9–18 UTC)
в течение 15 минут (`severity: warning`) — счётчик заявок не растёт.

## Что это значит

Канал создания заявок перестал работать, пока пользователи должны быть активны.
Это «тихая» деградация: ошибки могут быть только на фронтенде/шлюзе, API жив.

> Часовой пояс: `hour()`/`day_of_week()` — UTC. 9–18 UTC ≈ 12–21 MSK. Для другого
> пояса поправьте выражение в `infrastructure/observability/mimir/rules/anonymous/realhelpdesk.yml`.

## Диагностика

1. **Жив ли API**: `curl https://localhost:8443/api/v1/public/...` — 200?
   `up == 1`? Если API мёртв — это уже AppUnreachable, а не этот алерт.
2. **Фронтенд/шлюз**: проверить, что UI отдаётся, CDN/инверсия не в 5xx.
   Частая причина — фронт задеплоен с поломанным сабмитом формы.
3. **Метрики Mimir**: `curl -s -G localhost:9090/prometheus/api/v1/query --data-urlencode 'query=rate(tickets_total[5m])'`
   — «Заявки создано /мин» — как давно упала скорость (имя счётчика `tickets_total`, не
   `tickets_created_total`; серия появляется после первой заявки после старта — см. metrics.md);
   `curl -s -G localhost:9090/prometheus/api/v1/query --data-urlencode 'query=rate(http_server_requests_seconds_count{uri=~"/tickets.*",method="POST"}[5m])'` —
   ушёл ли POST /tickets (если GET есть, а POST нет — авторизация/валидация).
4. **Логи**: `{...="app"} |= "POST" |= "tickets"` — доходят ли запросы, какие ответы.
5. **Ложные срабатывания**: ночная/праздничная тишина в часовом поясе, отсутствие
   промо-трафика — порог нарочно осторожный, при повторе уточните сезонность.

## Митигация

- Откатить фронтенд/шлюз, если корреляция по времени.
- Если канальные интеграции (почта→тикет) — проверить health smtp и логи потребителей.
- Проверить, что миграция/валидация не отвергает все формы (`exception` в логах 4xx).
